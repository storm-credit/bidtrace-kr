# Workflow Registry 딥검수 결과

## 1. 검수 결론

사건 유형별 Workflow Registry의 1차 설계는 다음 범위를 충족한다.

- 기본 사건 유형 5종
- 특수권리 오버레이 1종
- 공통 Workflow Definition Contract
- 단계별 에이전트·모델 프로필·검토자
- 결정론 검사와 사람 승인 게이트
- 새 증거 유입 시 무효화 규칙
- 하네스 커버리지와 승격정책

그러나 아직 `운영 가능` 상태는 아니다. 현재 상태는 `design_draft`이며 실제 fixture, 모델 실행, MCP 보안 테스트와 외부 전문가 보정이 남아 있다.

---

## 2. 설계가 개선된 점

### 2.1 에이전트 목록이 실행계획으로 전환됐다

기존 설계는 역할과 책임을 정의했지만 사건 유형별 호출 순서가 완전히 닫혀 있지 않았다.

이번 Registry에서는 다음이 명시됐다.

- 어떤 단계에서 호출하는가
- 선행 입력은 무엇인가
- 병렬 또는 순차인가
- 누가 검토하는가
- 어떤 검사를 통과해야 하는가
- 어떤 자료가 들어오면 결과가 무효화되는가
- 어디에서 사람 또는 외부 전문가 승인이 필요한가

### 2.2 모든 전문가를 실행하지 않는다

사건 유형과 위험 신호에 따라 필요한 전문가만 호출한다.

예:

- 일반 아파트: 권리·시장·건축·금융·비용 중심
- 다가구: 임차인 Map-Reduce·합법 세대수·공실·운영 추가
- 토지: 진입·이용규제·소유불일치·특수권리 추가
- 지분: 공유자·점유·협상·환금성 추가
- 특수권리 신호: 외부 전문가 게이트 강제

### 2.3 안전한 상태전환이 강화됐다

다음은 이제 워크플로 수준에서 차단된다.

- 사람 승인 없는 잠금
- 특수권리 오버레이 누락
- 임차인 전원 처리 전 다가구 완료
- 대지권·소유관계 미확인 상태의 안전 판정
- 지분가치를 전체 물건가치와 혼합
- 확인되지 않은 개발계획을 확정 사실로 처리
- 새 등기 유입 후 오래된 권리분석을 계속 사용

## 3. 유형별 딥검수

### 3.1 표준 아파트

강점:

- 최소 실행경로가 명확하다.
- 권리와 시장·건축·금융 분석을 적절히 병렬화했다.
- 선순위 임차인과 특수권리 신호를 오버레이로 승격한다.

잔여 보강:

- 관리비 체납 처리 계약
- 단지별 동·층·향·수리상태 조정 규칙
- 재건축·리모델링 기대와 공식 진행단계 구분 fixture
- 경매개시 이후 새 임대차·점유변경 사례

### 3.2 다세대·연립

강점:

- 호실·토지·대지권 연결을 아파트와 분리했다.
- 위반 증축·다중 점유·낮은 유동성을 핵심 위험으로 처리한다.
- 토지 권리 불명확 상태에서 잠금을 차단한다.

잔여 보강:

- 대지권 미등기와 단순 문서누락을 구분하는 정책
- 집합건물 공용부분·전유부분 경계 fixture
- 실거래 비교사례 부족 시 평가 방법
- 전입세대·현황조사·현장 점유 충돌 fixture

### 3.3 다가구

강점:

- 임차인별 Map-Reduce 구조가 명시됐다.
- 임차인 신원 혼합과 보증금 합계 오류를 P0로 볼 수 있다.
- 합법 세대수와 관찰된 세대수를 분리한다.
- 공실·수리·운영 시나리오를 입찰계획에 연결한다.

잔여 보강:

- 임차인 데이터 최소 필드와 중복판정 기준
- 배당 계산 규칙의 시점별 정책 레지스트리
- 일부 임차인 자료만 확보된 경우 범위 추정 정책
- 관리비·공과금·보증금 반환·명도비의 중복 비용 방지
- 다가구와 사실상 다세대 사용의 분류 fixture

### 3.4 토지·건물

강점:

- 매각 범위와 소유구조를 첫 단계에서 분리한다.
- 진입로·이용규제·공식 개발계획을 별도 분석한다.
- 특수권리 외부 전문가 게이트가 강하다.

잔여 보강:

- 도로 접면·맹지 판단을 위한 지도·지적 자료 계약
- 농지·산지·개발행위 등 물건별 정책 오버레이
- 경계·현황 불일치와 측량 필요성
- 건축 가능성 판단을 자동화하지 않는 표현 정책
- 토지 가치 비교사례 품질 점수

### 3.5 지분경매

강점:

- 전체 물건가치와 지분가치를 분리한다.
- 공유자 점유와 물리적 분할 가능성을 별도 처리한다.
- 출구전략이 없으면 진행하지 않는 게이트가 있다.
- 법률·협상·보유기간 비용을 수익성에 반영한다.

잔여 보강:

- 공유자 관계정보의 합법적 수집 범위
- 협상 시나리오가 사실처럼 표시되지 않도록 하는 UX
- 전체지분 취득 가능성을 기본전제로 사용하지 않는 규칙
- 지분 거래사례가 없을 때 할인범위 설정 기준
- 장기보유와 소송 가능성을 별도 위험축으로 분리

### 3.6 특수권리 오버레이

강점:

- 특수권리를 단순 탐지 플래그로 끝내지 않는다.
- 공식자료 조사, 찬반 사실, Evidence Judge, 외부 전문가를 연결한다.
- 비용·지연·유동성 할인 반영을 강제한다.

잔여 보강:

- 특수권리별 독립 Workflow 또는 세부 하위 오버레이
- 외부 전문가 답변 형식과 책임범위 계약
- 판례·법령·정책 변경 감지 방식
- 유치권 주장처럼 현장 사실과 법률요건이 함께 필요한 fixture
- 전문가 간 의견 불일치 시 최종 표시 방식

## 4. 하네스에서 반드시 검증할 것

### 4.1 정적 계약 검사

- 모든 `depends_on`이 존재하는가
- 단계 DAG에 순환이 없는가
- agent_id와 service_id가 Registry에 존재하는가
- 고위험 작성단계에 독립 검토자가 있는가
- 사람 승인보다 잠금 단계가 앞서지 않는가
- 오버레이 활성 신호와 삽입단계가 연결되는가

### 4.2 합성 검사

예:

```text
WF-MULTIFAMILY-DAGAGU
+ suspected_senior_tenant
+ illegal_extension_signal
+ land_building_owner_mismatch
```

검사:

- 중복 에이전트 작업이 합쳐지는가
- 더 강한 게이트가 유지되는가
- 단계 의존성이 끊기지 않는가
- 외부 전문가 게이트가 누락되지 않는가
- 예상 비용과 실행시간이 계산되는가

### 4.3 무효화 검사

- 새 등기가 권리·입찰계획을 stale로 만드는가
- 새 현장사진이 건축·수리·시장조정만 무효화하는가
- 잠긴 V1은 보존되고 V2가 생성되는가
- 무효화된 결과를 PM이 다음 단계 입력으로 사용하지 않는가

### 4.4 보안 검사

- 한 사건 Worker가 다른 사건 증거를 읽을 수 없는가
- 특수권리 조사자가 Git 쓰기 권한을 얻지 않는가
- 외부 문서의 프롬프트 인젝션이 도구 권한을 넓히지 않는가
- 에이전트가 사람 승인 결과를 생성·수정하지 못하는가
- 잠금 서비스를 직접 호출할 수 없는가

---

## 5. 아직 픽스하면 안 되는 항목

다음은 fixture와 전문가 검증 전 확정하면 안 된다.

- 신뢰도 임계값
- 자료 freshness 일수
- 특정 모델 제품명
- 외부 전문가가 필수인 정확한 세부 범위
- 배당·세금·대출 정책 수치
- 지분 할인율
- 토지 이용가능성 판단 규칙
- 자동 제외 점수
- 모의입찰 절대 상한 산식

이 항목들은 정책 레지스트리와 평가 결과에 따라 버전 관리한다.

## 7. 현재 판정

| 항목 | 판정 |
|---|---|
| 사건 유형 분류 | 1차 FIX |
| 단계 구조 | 1차 FIX |
| 전문가 호출 순서 | 1차 FIX |
| 위험 오버레이 | HARDEN 필요 |
| 입력·출력 계약 | HARDEN 필요 |
| 정적 하네스 | 설계 완료, 미실행 |
| 실행 하네스 | 미실행 |
| 외부 전문가 보정 | 미실행 |
| 운영 승격 | 불가 |

Workflow Registry는 이제 구현 가능한 수준의 설계 골격을 갖췄다. 다만 실제 모델과 MCP를 연결하기 전에 fixture·정적검증·사람 승인 UX를 추가해야 한다.
