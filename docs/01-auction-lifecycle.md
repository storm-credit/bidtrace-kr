# 경매 사건 생애주기와 상태머신

## 1. 목적

경매 사건 하나가 물건 발견에서 사후 복기까지 어떤 상태를 거치는지 정의한다. 상태는 화면 표시용 라벨이 아니라 에이전트 실행과 사람 승인 조건을 통제하는 기준이다.

## 2. 상위 상태

```text
DISCOVERED
  ↓
DOCUMENTS_PENDING
  ↓
SCREENING
  ↓
RIGHTS_REVIEW ─┐
MARKET_REVIEW ─┼─ 병렬 가능
BUILDING_REVIEW┤
FIELD_REVIEW ──┘
  ↓
FINANCE_REVIEW
  ↓
BID_CANDIDATE
  ↓
BID_READY
  ↓
BID_LOCKED
  ↓
RESULT_TRACKING
  ↓
POST_AUCTION
  ↓
LEARNING_REVIEW
  ↓
CLOSED
```

어느 단계에서든 치명적 위험, 자료 부족, 사건 취하·변경 또는 사용자 판단에 따라 `ON_HOLD`, `EXCLUDED`, `CANCELLED`로 이동할 수 있다.

## 3. 상태별 정의

### 3.1 DISCOVERED

물건이 관심 목록에 등록된 상태.

필수 입력:

- 법원
- 사건번호 또는 임시 물건 ID
- 소재지
- 물건 종류
- 매각기일 또는 확인 예정일

완료 조건:

- 중복 사건 확인
- 추적 목적 등록
- 다음 검토일 지정

### 3.2 DOCUMENTS_PENDING

필수자료를 수집하는 상태.

필수자료 후보:

- 매각물건명세서
- 현황조사서
- 감정평가서
- 등기사항증명서
- 건축물대장
- 토지 관련 자료
- 매각기일·유찰 이력

전환 조건:

- 필수자료 최소 세트 확보 또는 미확보 사유 명시
- 문서별 기준일과 최신성 기록

### 3.3 SCREENING

정밀 분석 전 기본 필터링 단계.

검토 항목:

- 지역·물건 유형
- 감정가·최저가·유찰 횟수
- 예상 실투자금
- 사용자 투자 기준
- 명백한 제외 사유
- 자료 접근 가능성

출력:

- `PASS`
- `WATCH`
- `HOLD`
- `EXCLUDE`

### 3.4 RIGHTS_REVIEW

등기 순위, 임차인, 배당, 인수 가능 권리와 특수권리를 분석한다.

완료 조건:

- 권리 타임라인 작성
- 말소기준권리 후보와 근거 표시
- 임차인별 대항력·우선변제 관련 사실과 미확인 항목 표시
- 인수 가능 권리 후보 표시
- 특수권리 경고
- 독립 검토 또는 레드팀 완료

### 3.5 MARKET_REVIEW

실거래가, 호가, 임대료, 거래량과 처분기간을 분석한다.

완료 조건:

- 비교사례 선정 기준 기록
- 보수·기준·낙관 가격 범위
- 실거래와 호가 분리
- 이상치와 제외 사례 설명
- 분석 기준일 기록

### 3.6 BUILDING_REVIEW

건축·토지·공법 위험을 분석한다.

검토 항목:

- 건축물대장과 현황 일치 여부
- 위반건축물
- 대지권
- 용도와 구조
- 토지·건물 소유관계
- 접도와 이용 제한
- 다가구·다세대 구분
- 재개발·재건축 관련 사실과 불확실성

### 3.7 FIELD_REVIEW

현장과 점유 상태를 확인한다.

검토 항목:

- 실제 점유자 단서
- 외관·공용부·주차·접근성
- 누수·결로·균열·불법 증축 의심
- 관리비·체납 관련 확인 경로
- 중개업소 인터뷰
- 주변 임대·매매 수요

현장 미확인 시 `NOT_VISITED`를 명시하고 추정과 사실을 구분한다.

### 3.8 FINANCE_REVIEW

자금, 대출, 세금, 비용과 수익성을 검토한다.

필수 출력:

- 낙찰가별 자기자본
- 대출 가능액의 가정과 확인상태
- 취득·보유·처분 비용
- 수리·명도·공실·예비비
- 보수·기준·낙관 수익성
- 손익분기점
- 최대 입찰가 후보

### 3.9 BID_CANDIDATE

핵심 분석은 완료됐으나 추가 확인이나 승인 조건이 남은 상태.

출력 예:

```text
상태: 조건부 입찰 후보
필수 조건:
- 임차인 전입일 재확인
- 대출 최소 1.3억 확인
- 위반건축물 여부 현장 확인
- 최대 입찰가 1.87억 이하
```

### 3.10 BID_READY

모든 필수 게이트가 통과됐고 모의입찰 계획을 확정할 수 있는 상태.

전환 조건:

- 권리·시세·건축·자금 검토 완료
- 치명적 미확인 항목 해소 또는 사람의 조건부 승인
- 최대 입찰가와 포기 조건 확정
- 사용자 자금계획 확인

### 3.11 BID_LOCKED

모의입찰 계획이 스냅샷으로 잠긴 상태.

잠금 대상:

- 분석 기준일
- 증거 버전
- 에이전트·모델·프롬프트 버전
- 예상 낙찰가
- 목표 입찰가와 절대 상한가
- 예상 총투자금과 수익
- 핵심 위험과 포기 조건
- 사람 승인 기록

잠금 후 수정은 금지한다. 새 정보는 `Bid Plan V2`처럼 새 버전을 만든다.

### 3.12 RESULT_TRACKING

실제 매각 결과를 추적한다.

수집 항목:

- 매각 여부
- 낙찰가와 낙찰가율
- 입찰자 수
- 차순위 정보가 확인되는 경우 그 값
- 매각허가
- 잔금납부
- 재매각·취하·변경

### 3.13 POST_AUCTION

낙찰 이후 결과를 관찰한다.

추적 항목:

- 소유권 이전
- 점유 이전·명도
- 수리
- 임대 또는 매도 등록
- 실제 임대료·매도가
- 소요기간
- 추정 또는 확인된 추가비용

직접 낙찰받지 않은 물건은 공개적으로 확인 가능한 범위에서만 추적한다.

### 3.14 LEARNING_REVIEW

예상과 실제를 비교한다.

평가 항목:

- 낙찰가 예측 오차
- 시세 범위 적중 여부
- 수리비·명도기간 오차
- 임대료·매도가 오차
- 놓친 위험
- 과대평가한 위험
- 사람이 수정한 에이전트 판단
- 다음 사건에 적용할 규칙 후보

학습 결과는 바로 운영 정책을 변경하지 않는다. 벤치마크 검증과 PM 승인을 거쳐야 한다.

## 4. 예외 상태

### ON_HOLD

자료, 자금, 현장 또는 일정 문제로 잠시 중단.

### EXCLUDED

투자 기준 또는 위험 기준을 충족하지 못해 제외.

### CANCELLED

취하, 변경, 매각기일 소멸 등 사건 진행 자체가 중단.

### EXPERT_REVIEW_REQUIRED

법률·세무·건축·금융 전문가의 확인 없이는 진행할 수 없는 상태.

## 5. 상태 전환 공통 규칙

1. 완료 조건이 충족되지 않으면 PM은 다음 상태로 넘기지 않는다.
2. 상태 전환에는 실행자, 시간, 근거와 이유를 기록한다.
3. 과거 상태와 결과는 삭제하지 않는다.
4. 최신 자료가 들어오면 영향받는 분석을 `STALE`로 표시한다.
5. 권리와 자금 관련 치명적 변경은 `BID_READY`를 자동 해제한다.
6. 모의입찰 잠금 이후 새 정보는 새 버전으로만 반영한다.
7. 사건 종료 후에도 평가 데이터는 보존하되 개인정보는 최소화한다.

## 6. 진행률 표시

진행률은 단순 파일 개수가 아니라 필수 게이트 가중치로 계산한다.

예시:

- 사건·자료 15%
- 권리·임차인 25%
- 시세 15%
- 건축·현장 15%
- 자금·세금·수익 20%
- 입찰 승인 10%

치명적 필수 항목이 미완료이면 총점과 무관하게 `BID_READY`가 될 수 없다.
