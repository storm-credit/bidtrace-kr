# 에이전트 조직 설계 준비도와 잔여 과제

## 1. 결론

현재 설계는 **제안서와 상세기획 단계의 기준선으로 사용 가능한 수준**이지만, 구현을 바로 시작할 정도로 완벽하지는 않다.

설계 완성도를 단일 점수로 표현하면 다음과 같다.

| 영역 | 현재 준비도 | 판단 |
|---|---:|---|
| 제품 비전·범위 | 90% | 핵심 범위와 제외 범위가 명확함 |
| PM 오케스트레이션 | 88% | 제어·승인·무효화 원칙 확보 |
| 전문 에이전트 조직 | 85% | 포드·책임·호출등급 보강 완료 |
| 에이전트 입출력 계약 | 85% | 공통 계약 존재, 역할별 스키마 추가 필요 |
| 권리·임차인 | 75% | 1차 프레임워크 존재, 실제 사건 검증 필요 |
| 시장·비용·수익 | 72% | 계산 경계 존재, 정책·fixture 확장 필요 |
| MCP·Skills·Hooks | 70% | 권한 원칙 존재, 실제 서버 선정·테스트 필요 |
| 모델 라우팅 | 65% | 후보와 등급 존재, 벤치마크 미완료 |
| UX·사람 승인 | 45% | 정보구조만 있고 화면 검증 미완료 |
| 평가세트·회귀검증 | 40% | 합성 사례 일부만 존재 |
| 보안·개인정보 | 55% | 원칙 존재, 위협모델·보존정책 미완료 |
| 구현 아키텍처 | 35% | 코딩 전 단계로 의도적으로 보류 |

따라서 현재 상태는 다음과 같이 정의한다.

> “기획 방향이 잡힌 상태”를 넘어 “운영 가능한 조직과 계약을 설계한 상태”이지만, 실제 사건 평가와 UX·보안·정책 검증 전에는 최종설계로 확정하지 않는다.

## 2. 이번 에이전트 운영모델에서 보강된 사항

- 31개 논리 역할과 실제 런타임 인스턴스를 구분
- 역할을 7개 업무 포드와 Control Core로 재편
- 상시 제어서비스, LLM 에이전트, 독립 검토자, 결정론 모듈 분리
- 경매절차 전문 역할 추가
- 정책 최신성 전담 역할 추가
- 도시계획·재개발 전문 역할 추가
- 입지·인프라 전문 역할 추가
- 유동성·출구전략 전문 역할 추가
- 임대운영 전문 역할 추가
- Evidence Judge와 Learning Curator 추가
- 사건 유형별 최소 실행세트 정의
- Agent Task Contract 정의
- Specialist·Reviewer 공통 프롬프트 골격 정의
- 단계별 전달·검토·무효화 규칙 정의

## 3. 반드시 남아 있는 핵심 설계 과제

### G01. 역할별 개별 프롬프트

현재 공통 템플릿과 일부 핵심 프롬프트만 존재한다.

추가해야 하는 우선 프롬프트:

1. Auction Procedure Analyst
2. Document Quality Inspector
3. Registry Extractor
4. Sale Document Extractor
5. Building & Land Analyst
6. Special Rights Detector
7. Urban Planning & Redevelopment Analyst
8. Occupancy & Eviction Analyst
9. Finance Analyst
10. Tax & Cost Analyst
11. Renovation Cost Analyst
12. Rental Operations Analyst
13. Liquidity & Exit Analyst
14. Evidence Judge
15. Governance Reviewer
16. Postmortem Analyst

완료기준:

- 공통 템플릿 준수
- 역할별 입력·출력·승격조건 명시
- 금지행동 명시
- 합성 평가사례 2개 이상

### G02. 역할별 JSON Schema

현재 스키마는 논리 문서 중심이다.

추가 대상:

- evidence record
- extraction result
- rights decision candidate
- special-right escalation
- market comparable
- cost item
- finance assumption
- approval package
- review result
- invalidation event
- postmortem finding

### G03. 사건 유형별 Workflow Registry

필요한 워크플로:

- 일반 아파트
- 다세대·연립
- 다가구 다수 임차인
- 상가
- 토지
- 지분
- 유치권 주장
- 법정지상권 의심
- 대지권 미등기
- 토지·건물 소유자 불일치

각 워크플로에 다음을 지정해야 한다.

- 필수 증거
- 필수 에이전트
- 조건부 에이전트
- 자동중단 조건
- 사람 승인자
- 평가사례

### G04. 공식 정책 레지스트리

법령·세금·대출·공공데이터 기준은 시점에 따라 바뀐다.

필요 항목:

- policy_id
- 공식 출처
- 적용일
- 만료 또는 재확인일
- 영향을 받는 에이전트와 계산식
- 변경 시 무효화 범위

### G05. 모델 벤치마크

모델명 선정을 문서 선호로 확정하면 안 된다.

필수 평가:

- 한국어 법률문서 표 추출
- 등기 타임라인 구성
- 근거 없는 사실 생성률
- 반대해석 품질
- 장문 PDF 처리
- 구조화 출력 성공률
- 비용·지연
- 공급자 장애 시 대체성

### G06. MCP 실제선정과 위협모델

필요한 MCP 후보군:

- GitHub
- Filesystem
- PDF·문서 추출
- 브라우저·공식자료 조사
- 공공데이터
- PostgreSQL
- 계산기
- 지도·공간정보
- 알림

각 서버별 검토:

- 운영주체
- 인증방법
- 데이터 반출
- read/write 범위
- prompt injection 위험
- 로그 보존
- 장애 시 행동
- 에이전트별 allowlist

### G07. 사람 승인 UX

법률·투자 위험을 긴 보고서만으로 승인시키면 안 된다.

반드시 검증할 화면:

- 핵심 사실
- 치명적 unknown
- 반대해석
- 비용 스트레스
- 조건부 승인조건
- 외부전문가 질문
- 잠금될 내용

### G08. 실제 사건 평가세트

합성 사례만으로는 충분하지 않다.

개인정보를 제거한 실제 또는 공개 사건 기반으로 다음을 구성해야 한다.

- 일반 사건
- 선순위 임차인
- 다가구 다수 임차인
- 유치권 주장
- 법정지상권
- 지분
- 위반건축물
- 대지권 문제
- 시세 표본 부족
- 비용 누락
- 대출 미확인
- 낙찰 후 결과 추적

### G09. 개인정보·보안 설계

필요 항목:

- 주민·임차인 개인정보 최소화
- 원본 접근등급
- 마스킹·가명처리
- 보존기간
- 삭제정책
- 로그에 남기지 않을 데이터
- 외부 LLM 전송 허용범위
- 로컬 모델 사용조건
- 비밀정보와 API 키 저장

### G10. 실패복구와 관찰성

필요 항목:

- 에이전트 타임아웃
- 모델 공급자 장애
- MCP 장애
- 부분 성공
- 중복 실행
- idempotency
- 비용 상한
- task lineage
- 사람 승인 대기
- 장기 추적 재개

## 4. 과도한 에이전트화를 막기 위한 확정 원칙

전문 역할을 발견할 때마다 별도 LLM을 추가하지 않는다.

새 에이전트 생성 조건:

1. 독립된 전문 지식이 필요하다.
2. 별도의 입력·출력 소유권이 있다.
3. 기존 역할과 다른 도구 권한이 필요하다.
4. 독립 평가가 가능하다.
5. 오류가 다른 유형의 위험을 만든다.

다음은 새 에이전트가 아니라 규칙 또는 프롬프트 옵션으로 처리한다.

- 단순 문체 변경
- 같은 데이터를 다른 표로 표시
- 동일 계산의 반복
- 동일 전문성의 지역명 변경
- 저위험 체크리스트 생성
