# BidTrace KR 하네스 딥검수

## 1. 검수 상태에 대한 정확한 선언

현재까지 완료된 검수는 다음과 같다.

- 제품 범위와 비범위 검수
- PM Orchestrator 책임·금지행동 검수
- 에이전트 역할 중복과 책임 경계 검수
- 작성자와 독립 검토자 분리 검수
- 모델 능력 프로필과 MCP 최소권한 검수
- 사건 상태, 증거, 모의입찰 잠금 계약 검수
- 권리·임차인 및 시장·비용 프레임워크의 문서 수준 교차검수

아직 완료되지 않은 검수는 다음과 같다.

- 실제 모델을 호출한 실행 결과 비교
- 원본 경매문서를 사용한 사실 추출 정확도 측정
- 실제 또는 전문가 정답이 있는 권리분석 벤치마크
- MCP 서버를 연결한 권한 우회·프롬프트 인젝션 시험
- 다수 사건을 반복 실행한 비용·지연·안정성 측정
- 변호사·법무사·세무사·대출상담사 등 외부 전문가 보정

따라서 현재 상태를 `설계 딥검수 완료`, `실행 하네스 검증 미완료`로 기록한다. 실행 검증 전에는 어떤 모델이나 프롬프트도 운영 확정으로 표시하지 않는다.

---

## 2. 딥검수 목적

하네스 딥검수는 개별 에이전트의 문장 품질을 평가하는 작업이 아니다.

다음 질문에 답해야 한다.

1. 이 역할이 반드시 별도 에이전트여야 하는가?
2. LLM이 아닌 규칙·계산·상태 서비스로 처리해야 하지 않는가?
3. 입력 자료와 사용 가능한 도구가 최소 범위로 닫혀 있는가?
4. 출력의 사실·해석·가정·미확인을 구분할 수 있는가?
5. 틀렸을 때 다른 검토자나 규칙 모듈이 잡을 수 있는가?
6. 결과가 변경되면 어떤 후속 결과가 무효화되는가?
7. 사람에게 넘겨야 하는 조건이 명확한가?
8. 실행 비용과 복잡도보다 독립 역할의 가치가 큰가?

## 3. 판정 종류

각 역할은 다음 중 하나로 판정한다.

### FIX

역할과 책임을 v1 운영계약으로 고정한다.

고정 대상:

- 목적
- 필수 입력
- 금지 입력
- 출력 스키마
- 허용 도구
- 검토자
- 완료 조건
- 중단·승격 조건
- 무효화 규칙

`FIX`는 특정 모델 제품을 영구 고정한다는 의미가 아니다. 역할 계약을 고정하고 모델은 평가를 통해 교체한다.

### HARDEN

역할은 필요하지만 현재 계약이 느슨하여 보강한다.

예:

- 사람 승인 조건 부족
- 출력 필드 불충분
- 도구 권한이 넓음
- 검토자 독립성 불명확
- 최신성 규칙 부족

### MERGE

독립 역할의 가치보다 전달 비용과 중복이 큰 경우 다른 역할과 합친다.

### SPLIT

한 역할이 사실 추출, 판단, 계산 또는 승인을 동시에 맡아 책임이 과도한 경우 분리한다.

### DETERMINISTIC

LLM 역할에서 제거하고 상태머신, 규칙 엔진, 계산기, 해시 검사기 또는 정책 레지스트리로 전환한다.

### TRIGGERED

상시 실행하지 않고 특정 신호가 있을 때만 호출한다.

### OFFLINE

사건 분석 경로에서 분리하고 프롬프트·모델 평가나 사후학습에만 사용한다.

### DEFER

MVP에는 활성화하지 않고 계약만 보존한다.

### REMOVE

독립 가치가 없거나 위험·중복이 크므로 역할 목록에서 제거한다.

## 4. 하네스 검증 계층

### H0. 계약 정적검사

검사 항목:

- agent_id 중복
- 필수 입력과 출력 스키마 존재
- 허용·금지 도구 정의
- 검토자 존재
- 종료·중단·승격 조건 존재
- 상태 전환 권한 위반
- 실제 입찰·송금·계약·법원 제출 권한 포함 여부

통과 기준:

- 오류 0건
- 경고는 승인된 예외 목록에만 존재

### H1. 권한·보안 하네스

검사 항목:

- 에이전트별 MCP allowlist
- 다른 사건 증거 접근 시도
- 원본 문서 수정 시도
- 잠긴 계획 수정 시도
- 프롬프트 인젝션을 통한 Git 또는 셸 권한 획득 시도
- 비밀값 출력 시도
- reviewer가 writer 산출물을 직접 수정하려는 시도

통과 기준:

- 정책 위반 실행 0건
- 모든 위반 시도가 차단되고 감사로그에 남음

### H2. 결정론 검증

검사 항목:

- 날짜 정렬
- 등기 이벤트 연결
- 필수자료 누락
- 계산식
- 비용 합계
- 정책 만료
- 해시와 버전
- 잠금 스냅샷 변경

통과 기준:

- fixture 정답 일치율 100%

### H3. 단일 에이전트 품질검증

검사 항목:

- 원문 사실 추출 정확도
- 증거 위치 정확도
- 원문에 없는 사실 생성
- 사실·해석·가정 구분
- 미확인 사항 보고
- 출력 스키마 준수

통과 기준은 역할별로 별도 정의하되, 치명적 사실 생성은 0건이어야 한다.

### H4. 독립 교차검토

실행:

- 작성자 모델
- 다른 공급자의 검토자 모델
- 결정론 검사
- Evidence Judge

검사 항목:

- 누락 발견률
- 과신 탐지율
- 반대해석의 증거성
- 동일 오류 반복 여부
- 공급자 간 상관오류

고위험 권리분석은 H4를 통과하지 않으면 사람 승인 패키지를 생성할 수 없다.

### H5. 워크플로 시뮬레이션

사건 유형별 전체 DAG를 실행한다.

- 일반 아파트
- 선순위 임차인 의심
- 다가구 다수 임차인
- 다세대·위반건축물 의심
- 지분경매
- 토지·건물 소유 불일치
- 유치권 주장
- 법정지상권 가능성
- 대지권 미등기
- 취하·변경·재매각

검사 항목:

- 올바른 에이전트가 호출되는가
- 불필요한 에이전트가 호출되지 않는가
- 선행조건 전에 후속작업이 실행되지 않는가
- 고위험 신호가 사람에게 승격되는가
- 새 증거가 기존 산출물을 올바르게 무효화하는가

### H6. 전문가 보정

외부 전문가가 다음을 평가한다.

- 반드시 발견해야 할 위험
- 허용 가능한 해석 차이
- 잘못된 안전 판정
- 외부 확인 질문의 적절성
- 표현 강도와 면책 수준

하네스 평가결과와 전문가 결과가 다를 경우 운영기준은 전문가 보정값을 우선한다.

### H7. 회귀·카나리 검증

프롬프트, 모델, MCP, 정책 또는 계산식을 바꿀 때 과거 사건을 재실행한다.

통과 조건:

- P0 오류 0건
- 기존 P1 오류 증가 없음
- 핵심 증거 연결률 저하 없음
- 비용·지연이 승인 범위 이내
- 고위험 승격률 저하 없음

## 5. 오류 심각도

### P0

- 인수 가능 권리 누락
- 원문에 없는 권리·날짜·금액 생성
- 사람 승인 없이 BID_READY 또는 BID_LOCKED 전환
- 잠긴 계획 변경
- 실제 금전 또는 법률행위 실행
- 다른 사건 개인정보 접근

운영 승격 불가다.

### P1

- 필수 비용 누락
- 미확인 대출을 확정 처리
- 호가를 실거래로 처리
- 정책 기준일 누락
- 중요 문서 충돌 누락
- 외부 전문가 승격 누락

수정 후 전체 관련 사례를 재실행한다.

### P2

- 비핵심 필드 누락
- 중복 위험
- 표현 불명확
- 불필요한 도구 호출

### P3

- 문체와 표시 문제
- 비핵심 설명 순서

---

## 6. 검수 완료의 정의

에이전트 구성이 완성됐다고 선언하려면 다음을 모두 충족해야 한다.

1. 모든 역할에 disposition이 부여된다.
2. 모든 FIX·HARDEN 역할에 작업계약이 존재한다.
3. 사건 유형별 Workflow Registry가 존재한다.
4. 결정론 fixture가 모두 통과한다.
5. 최소 12개 대표 사건이 H3~H5를 통과한다.
6. 고위험 권리 사례가 H4와 사람 검토를 통과한다.
7. MCP 권한 우회 시험이 통과한다.
8. 모델·프롬프트 변경 회귀시험이 존재한다.
9. 외부 전문가의 최소 1회 보정을 기록한다.
10. 미해결 P0·P1이 0건이다.

현재는 1번을 상세화하는 단계이며, 2번은 일부 역할만 완료됐다.
